
Control: V-206604

Requirement:

Configure the DBMS, OS, and relevant software to provide the required level of cryptographic protection for information requiring protection against disclosure.

This is risk-based.

It does not automatically require:
	•	Encryption-at-rest
	•	TLS everywhere
	•	TDE
	•	Disk encryption

It requires the system to meet the cryptographic protection level appropriate to the data type.

⸻

🎯 What Data Does SonarQube Store?

SonarQube PostgreSQL backend typically stores:
	•	Source code analysis results
	•	Project metadata
	•	Quality metrics
	•	Issue tracking data
	•	User accounts
	•	Hashed credentials (if local auth used)
	•	Tokens (hashed)
	•	Plugin configs

It does not typically store:
	•	PII
	•	PHI
	•	Classified data
	•	Financial data
	•	Secrets in plaintext (unless misconfigured)

🧠 Does SonarQube Require Encryption-at-Rest?

For most DevOps / CI environments:
	•	SonarQube data is considered internal operational data
	•	Not classified or regulated data
	•	Not high-impact confidentiality data

For typical internal DevSecOps environments:

Disk encryption is recommended but not strictly required by SRG wording unless system categorization mandates it.

🚨 When It Would Become a Finding

If:
	•	SonarQube stores regulated data
	•	DB exposed over network without TLS
	•	FIPS disabled
	•	Weak crypto algorithms allowed
	•	System categorized High/IL5+
	•	Organizational policy mandates encryption-at-rest

Then it could become a finding.

Implementation Summary

The PostgreSQL instance supports a SonarQube service in an isolated, localhost-only deployment. The system:
	•	Operates on RHEL 8.x with FIPS mode enabled
	•	Uses FIPS 140-validated cryptographic modules
	•	Enforces system crypto policy set to FIPS
	•	Does not expose database services over a network
	•	Restricts access via SELinux and strict filesystem permissions

The database stores internal application analysis data and operational metadata. No external data transmission occurs.

⸻

Conclusion

The DBMS and operating system are configured to provide the required level of cryptographic protection for the system’s operational classification.

V-206604 is Not a Finding.
