Develop, document, and implement procedures to restrict and track use of the DBMS software installation account.

This version is structured for RMF submission, ISSO review, and audit evidence packaging.

⸻

🛡 SRG Compliance Artifact

Control ID: V-206545

Title: Restrict and Track Use of the DBMS Software Installation Account

Severity: CAT II

System: PostgreSQL 15/16 on Red Hat Enterprise Linux 8

⸻

1️⃣ Control Requirement

The organization must:

Develop, document, and implement procedures to restrict and track use of the DBMS software installation account.

For PostgreSQL on RHEL systems, the installation account typically includes:
	•	The operating system account: postgres
	•	The PostgreSQL superuser role: postgres
	•	Any privileged account used to install, configure, patch, or maintain PostgreSQL software

⸻

2️⃣ Control Objective

Ensure that:
	•	The DBMS installation account is restricted to authorized administrators only
	•	Direct interactive login is prevented
	•	Privileged access is controlled via sudo
	•	Privileged DB actions are logged
	•	Account usage is auditable
	•	Procedures governing its use are formally documented

⸻

3️⃣ Implementation Summary

Requirement	Implementation Method
Restrict OS login	Disable interactive shell for postgres
Controlled elevation	Sudo-based access via DBA group
Limit DB superusers	Only postgres role has SUPERUSER
Log privileged DB actions	pgaudit enabled
Log OS-level usage	auditd rules applied
Document procedures	Administrative SOP maintained


⸻

4️⃣ Technical Implementation Details

⸻

4.1 Restrict Interactive OS Login

The postgres OS account is configured with a non-login shell:

usermod -s /sbin/nologin postgres

Verification:

getent passwd postgres

Expected shell:

/sbin/nologin

This prevents direct SSH login to the installation account.

⸻

4.2 Enforce Controlled Sudo Access

Access to the postgres account is limited to authorized DBAs via group-based sudo.

File:

/etc/sudoers.d/postgres_admins

Configuration:

%dbadmins ALL=(postgres) ALL

Only members of the dbadmins group may assume the postgres account.

All sudo actions are logged in:

/var/log/secure


⸻

4.3 Restrict Database Superuser Privileges

Within PostgreSQL:

SELECT rolname
FROM pg_roles
WHERE rolsuper = true;

Expected result:

postgres

No application or service account is granted SUPERUSER privileges.

⸻

4.4 Enable Privileged Activity Logging (pgaudit)

PostgreSQL is configured with:

shared_preload_libraries = 'pgaudit'
pgaudit.log = 'role, ddl, write'
log_connections = on
log_disconnections = on

This ensures:
	•	Role changes logged
	•	DDL activity logged
	•	Privileged write activity logged
	•	Login/logout events logged

Logs are retained in the PostgreSQL log directory and forwarded to centralized logging where applicable.

⸻

4.5 Track OS-Level DBMS Binary Usage

RHEL auditd rules monitor execution of PostgreSQL binaries:

File:

/etc/audit/rules.d/postgres.rules

Example configuration:

-w /usr/pgsql-16/bin/psql -p x -k postgres_install_usage
-w /usr/pgsql-16/bin/postgres -p x -k postgres_install_usage

Audit records stored in:

/var/log/audit/audit.log


⸻

5️⃣ Administrative Procedures

The organization maintains a documented Standard Operating Procedure (SOP) titled:

PostgreSQL Administrative Account Usage Policy

The SOP includes:
	1.	Only designated DBAs may access the installation account
	2.	Direct SSH login to postgres is prohibited
	3.	Access must be via sudo from a named user account
	4.	Shared credentials are prohibited
	5.	Administrative sessions must be logged
	6.	Privileged activity logs are reviewed weekly
	7.	Log retention: minimum 90 days

Document Location:

/security/sops/postgresql_install_account_policy.docx

8️⃣ Risk Analysis

If the installation account were unrestricted:
	•	Full OS and DB compromise possible
	•	Unauthorized configuration changes
	•	Persistence mechanisms could be installed
	•	Lack of traceability

Mitigations implemented:
	•	No direct login
	•	Controlled sudo access
	•	Audit logging enabled
	•	Regular log review
	•	Least privilege enforcement

Residual Risk Level: Low

🏁 Final Statement

The PostgreSQL installation account (postgres) is restricted to authorized personnel, access is controlled via sudo, privileged database actions are audited, and OS-level execution of PostgreSQL binaries is tracked. Documented administrative procedures govern its use and review.

The system satisfies the requirements of STIG V-206545.
