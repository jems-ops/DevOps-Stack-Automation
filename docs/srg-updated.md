## PostgreSQL SRG Compliance Artifact

| Control ID | Status | Finding Details | Comment | Mitigation | Mitigation Control |
|-------------|--------|----------------|---------|------------|--------------------|
| V-206520 | Remediated | The DBMS was not configured to integrate with centralized authentication or restrict access appropriately. | PostgreSQL instance restricted to localhost with controlled login roles. Centralized authentication not required in isolated deployment architecture. | Restrict DB network exposure and remove unauthorized login roles. | PostgreSQL configured with `listen_addresses='localhost'`, `pg_hba.conf` hardened, and login roles restricted. |
| V-206521 | Remediated | Database users could potentially access objects beyond authorized scope due to default privileges. | PUBLIC privileges revoked and role-based access control enforced for schemas and objects. | Implement least privilege access controls. | RBAC model implemented and PUBLIC privileges removed from database and schema objects. |
| V-206545 | Remediated | DBMS installation account usage was not restricted or auditable. | Interactive login disabled for the `postgres` account and access controlled through authorized DBA sudo group. | Restrict installation account access and enforce auditing. | Controlled privilege escalation through sudo and audit logging enabled for administrative actions. |
| V-206555 | Remediated | Database roles contained stored password credentials and password-based authentication methods were present. | Password authentication disabled and roles with stored passwords removed. | Eliminate stored database passwords. | Peer authentication enforced and stored password hashes removed from roles. |
| V-206556 | Remediated | Password artifacts such as `.pgpass` files or stored credentials could expose authentication secrets. | `.pgpass` files removed and password artifacts eliminated from system directories. | Remove stored authentication secrets. | File system scans implemented to remove credential files and protect configuration files. |
| V-206557 | Remediated | Database authentication mechanisms could allow transmission of plaintext passwords across the network. | Database connections restricted to localhost and secure authentication mechanisms enforced. | Prevent plaintext credential transmission. | SCRAM or peer authentication enforced and external network exposure disabled. |
| V-206559 | Remediated | DBMS PKI private keys were potentially stored within the database environment. | No PKI keys stored in PostgreSQL environment and SSL disabled for this architecture. | Eliminate storage of private key material within DBMS. | Removal of server certificate and key files from PostgreSQL data directory. |
| V-206561 | Remediated | Authentication secrets could be exposed through configuration files or environment variables. | Removal of `.pgpass` files and scanning for exposed password strings. | Prevent exposure of authentication secrets. | Automated configuration scanning ensures credentials are not present in files or environment variables. |
| V-206562 | Remediated | Cryptographic operations were not verified to use FIPS validated modules. | System crypto policy configured for FIPS mode through the hardened operating system baseline. | Enforce FIPS validated cryptographic modules. | PostgreSQL relies on OpenSSL libraries configured through OS-level FIPS crypto policies. |
| V-206570 | Remediated | Database files were not sufficiently protected at the operating system level. | Data directory ownership, permissions, and file protections enforced. | Restrict file system access to database files. | PostgreSQL data directory secured with ownership `postgres:postgres` and permissions `0700` with SELinux enforcing. |
| V-206604 | Remediated | Cryptographic protections for data were not verified to meet system security requirements. | System crypto policies enforce approved cryptographic algorithms. | Enforce system cryptographic policies. | PostgreSQL inherits cryptographic protections from the RHEL FIPS crypto policy configuration. |
| V-206605 | Remediated | DBMS cryptographic mechanisms were not verified against system classification requirements. | Cryptographic protections aligned with system classification through FIPS-enabled OS configuration. | Enforce approved cryptographic mechanisms. | PostgreSQL uses OpenSSL FIPS cryptographic providers managed by the operating system. |
| V-233495 | Remediated | DBMS deployment did not confirm compatibility with NSA-approved cryptographic standards. | System configured to use FIPS cryptographic modules and weak authentication mechanisms removed. | Deploy DBMS using NSA-approved cryptography. | System crypto policy set to FIPS and weak authentication methods disabled. |
| V-265854 | Remediated | DBMS version support status was not validated. | PostgreSQL server version validated to ensure it is a supported release. | Ensure DBMS version is vendor supported. | Automated validation confirms PostgreSQL version aligns with supported release lifecycle. |
