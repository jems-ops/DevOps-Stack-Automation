## PostgreSQL SRG Remediation Artifact

| Control ID | Status | Finding Details | Comment | Mitigation | Mitigation Control |
|------------|--------|----------------|---------|------------|--------------------|
| V-206520 | Remediated | DBMS authentication integration and access restrictions were not clearly enforced. | **Remediated.** PostgreSQL access is restricted to localhost and approved login roles only. Verification: run `SHOW listen_addresses;` and review `pg_hba.conf` to confirm only authorized authentication methods and local access are configured. | Restrict DB network exposure and remove unauthorized login roles. | PostgreSQL configured with `listen_addresses='localhost'` and hardened `pg_hba.conf`. |
| V-206521 | Remediated | Default privileges allowed broader access to database objects than authorized. | **Remediated.** PUBLIC privileges revoked and RBAC implemented. Verification: run `SELECT datacl FROM pg_database WHERE datname=current_database();` and check schema ACLs using `SELECT nspname,nspacl FROM pg_namespace;`. | Implement least privilege access controls. | RBAC model implemented and PUBLIC privileges removed from database and schema objects. |
| V-206545 | Remediated | DBMS installation account usage was not restricted or tracked. | **Remediated.** The `postgres` installation account is restricted from direct login and usage is auditable. Verification: run `getent passwd postgres` to confirm restricted shell and check audit logs or `pgaudit` configuration. | Restrict installation account access and enable auditing. | Access controlled through DBA sudo group and audit logging enabled. |
| V-206555 | Remediated | Database roles stored password credentials and password authentication methods existed. | **Remediated.** Password authentication removed and stored credentials cleared. Verification: query `SELECT rolname FROM pg_authid WHERE rolpassword IS NOT NULL;` and inspect `pg_hba.conf` for absence of password methods. | Eliminate stored database passwords. | Peer authentication enforced and stored passwords removed from roles. |
| V-206556 | Remediated | Password artifacts such as `.pgpass` files could expose credentials. | **Remediated.** Credential files removed and environment secrets eliminated. Verification: run `find / -name ".pgpass"` and confirm no password artifacts exist. | Remove stored authentication secrets. | Automated file scans remove `.pgpass` and protect configuration files. |
| V-206557 | Remediated | Passwords could potentially be transmitted in plaintext across the network. | **Remediated.** Secure authentication enforced and DB restricted to localhost. Verification: review `pg_hba.conf` to confirm peer or SCRAM authentication and run `ss -tulnp | grep 5432` to confirm local binding. | Prevent plaintext credential transmission. | Secure authentication enforced and network exposure disabled. |
| V-206559 | Remediated | DBMS PKI private keys could be stored in the database environment. | **Remediated.** No PKI keys stored and SSL disabled for this architecture. Verification: check PostgreSQL configuration `SHOW ssl;` and confirm no `server.key` exists in the data directory. | Remove private key material from DBMS environment. | SSL disabled and certificate/key files removed. |
| V-206561 | Remediated | Authentication secrets could appear in configuration files or environment variables. | **Remediated.** Secret exposure prevented by removing `.pgpass` and scanning configuration files. Verification: run `grep -R password= $PGDATA` and check environment variables for credential exposure. | Prevent exposure of authentication secrets. | Automated scans remove credential artifacts and protect configuration files. |
| V-206562 | Remediated | Cryptographic modules used by the system were not verified as FIPS validated. | **Remediated.** System crypto policy configured to enforce FIPS modules. Verification: run `cat /proc/sys/crypto/fips_enabled` and `update-crypto-policies --show`. | Enforce FIPS validated cryptographic modules. | PostgreSQL uses OpenSSL libraries controlled by OS FIPS policy. |
| V-206570 | Remediated | Database files were not sufficiently protected at the OS level. | **Remediated.** Data directory ownership and permissions enforced. Verification: run `stat $PGDATA` and confirm owner `postgres` and permissions `0700`. | Restrict filesystem access to database files. | PostgreSQL data directory secured with strict permissions and SELinux enforcing. |
| V-206604 | Remediated | Cryptographic protections for data were not verified against required system policies. | **Remediated.** System crypto policy enforces approved algorithms. Verification: run `update-crypto-policies --show` and confirm policy `FIPS`. | Enforce system cryptographic policies. | PostgreSQL relies on OS-level FIPS crypto configuration. |
| V-206605 | Remediated | DBMS cryptographic protections not validated against classification requirements. | **Remediated.** Database inherits approved cryptographic configuration from the hardened OS baseline. Verification: check FIPS mode with `cat /proc/sys/crypto/fips_enabled`. | Enforce approved cryptographic mechanisms. | PostgreSQL uses OpenSSL FIPS cryptographic providers managed by the OS. |
| V-233495 | Remediated | DBMS compatibility with NSA-approved cryptographic standards was not verified. | **Remediated.** Weak authentication methods removed and FIPS crypto policy enforced. Verification: run `update-crypto-policies --show` and review `pg_hba.conf` to confirm no `md5` authentication methods. | Deploy DBMS with NSA-approved cryptography. | System crypto policy set to FIPS and weak authentication disabled. |
| V-265854 | Remediated | DBMS version support status was not validated. | **Remediated.** PostgreSQL version validated to ensure vendor support. Verification: run `psql -c "SHOW server_version;"` and confirm version matches approved supported releases. | Ensure DBMS version is supported by vendor lifecycle. | Automated validation checks PostgreSQL version compliance. |
